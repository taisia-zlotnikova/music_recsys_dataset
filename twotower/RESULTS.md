# Пилот v2: encoder–decoder с LoRA

Train: 50 000 диалогов / 82 122 хода. Val: 5000 диалогов / 8421 ход.
Каталог: 32 462 трека. Граница исходного split: 2018-08-06 UTC, пересекающие диалоги исключены.
Qwen3-Embedding-0.6B, E=2, cross_every=4, LoRA r=8 во всех attention, исходные Transformer-веса заморожены.
Признаки: frozen MuQ-128, frozen Qwen-название-1024, обучаемые теги-256.
Три отдельных обучения: 4 эпохи / 2568 шагов, эффективный batch 128, seed 42.
Лучший checkpoint выбирался по NDCG@100 на фиксированных 5000 val-ходах; итоговая оценка — все 8421.

## Проверка истории (CPU FP32, те же 8421 хода)

Both: настоящая история R@100=0.5087, пустая=0.2959, чужая=0.2468.
History: настоящая=0.0657, чужая=0.0207. Доноры — фиксированная перестановка между разными пользователями.
Вмешательство в готовую модель не заменяет отдельное обучение без истории.

Выигрыш both над recency неоднороден:
- Первые ходы: Recall@100 0.5013 против 0.5010; NDCG@100 0.2053 против 0.2147.
- Последующие: Recall@100 0.5196 против 0.4369; NDCG@100 0.2072 против 0.1302.
- Общий выигрыш Recall@100 +3.38 п.п., 95% bootstrap CI [+1.59; +5.06] п.п.

Цели вне исходной истории: recall@100 both=0.4459, text=0.3820, recency=0.0174.
Среднее считается по ходам с непустым соответствующим подмножеством целей.
History-only получает градиенты во всех проверенных обучаемых ветках, реагирует на историю,
но top-1 содержит лишь 154 разных трека на 8421 ход (у both 4025). Причина низкого качества окончательно не установлена.

## Усечение истории на инференсе

Веса во всех строках обучены с лимитом 64. Это не сравнение обучений с разной длиной.

| Модель | История | Recall@10 | Recall@100 | NDCG@100 |
|---|---:|---:|---:|---:|
| Both | 16 | 0.2351 | 0.5046 | 0.2080 |
| Both | 32 | 0.2366 | 0.5079 | 0.2079 |
| Both | 64 | 0.2343 | 0.5087 | 0.2060 |
| History | 16 | 0.0118 | 0.0650 | 0.0176 |
| History | 32 | 0.0122 | 0.0665 | 0.0180 |
| History | 64 | 0.0116 | 0.0657 | 0.0178 |

History/64: Recall@1000=0.2691, Recall@10000=0.7643; медианный ранг цели по вхождениям — 3318.
Цели часто находятся далеко за top-100, поэтому переранжирования первой сотни недостаточно.
В истории 64 уже содержится в среднем 46.57% целей, но recall по присутствующим целям всего 6.72%.
Увеличение истории до 128 пока не обосновано как решение: модель слабо использует уже доступные цели.

Следующий ограниченный запуск — новое обучение both с историей 32 на четыре эпохи.
Готовый notebook: [colab_ablations.ipynb](colab_ablations.ipynb), по умолчанию history32.
Другие подготовленные варианты: no_tags и no_audio, каждый меняет один фактор относительно both/64.

## Воспроизводимость и ограничения

Команды и требования: [README.md](README.md). Код диагностики: diagnose.py, history_sweep.py.
Требуются отдельные features.npz, pilot/ и checkpoint; они не хранятся в Git.
Локальные подробные результаты: runs/lora_v2_e2/diagnostics_cpu/ и history_sweep/.
Исходные данные, предсказания, checkpoint и личная переписка не публикуются.

Один seed, пилотная выборка и validation, использовавшаяся для выбора checkpoint; отдельного test нет.
Bootstrap — 2000 повторов по диалогам, разные диалоги одного пользователя не объединяются.
Интервалы не отражают разброс обучения по seed. CPU FP32 воспроизводит Colab FP16
с отличиями Recall@100 не более 0.037 п.п.
